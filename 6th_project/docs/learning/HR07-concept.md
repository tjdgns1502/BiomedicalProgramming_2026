# HR07 · CONCEPT — 문제 추적, 검증 범위, 결론의 한계

> 일반 통계 개념 페이지. 예시는 모두 **🧪 가상**. 실제 적용은 [HR07-paper](HR07-paper.md).

## 입력
분석 중 생긴 의문, 실행 기록, 검토 결과, 원문 주장.

## 이번 질문
"무엇을 확인했고, 무엇을 확인하지 못했으며, 그래서 결론은 어디까지 말할 수 있는가?"

## 방법과 이유

### 문제 ID로 추적하기
의문마다 ID를 붙이고 다음을 적는다: 출처(어느 셀·문장), 종류(미공개 설정 / 자료 품질 / 타당성 / 범위), 결과를 바꿀 가능성, 필요한 증거, 조치, 상태(해결 / 부분 해결 / 미해결 / 범위 밖).
🧪 예: "ISS-xx: B열 헤더가 코드북과 다르다 → 코드북 정의 + 같은 시점 다른 열과의 값 일치로 확인 → 해결."

### 서로 다른 '통과'를 섞지 않기
| 상태 | 뜻 | 뜻하지 않는 것 |
|---|---|---|
| 코드가 오류 없이 끝남 (exit 0) | 실행됨 | 계산이 맞음 |
| 공식 검사 통과 | 내장함수 = 교과서 공식 | 자료 매핑이 맞음 |
| 검토 통과 | 검토자가 본 범위에서 문제 없음 | 검토 범위 밖도 맞음 |
| 통계적 유의 | 귀무가설과 맞지 않음 | 효과가 크거나 중요함 |
| 논문 수치 일치 | 같은 숫자가 나옴 | 방법이 타당함 |

### 근거의 종류
원문 보고 / 코드북 확인 / 관측 자료 / 분석자 가정 / 재현 후보 / 미확인 / 상충. 다음 사람에게 넘길 때 **종류를 바꾸지 않는다**. "재현 후보"가 어느새 "저자 방법"으로 바뀌는 것이 흔한 오류다.

### 검토의 독립성
같은 사람(또는 같은 AI)이 쓴 코드를 다시 읽는 것은 자기 검토다. 다른 문맥의 검토자를 쓰면 나아지지만, 그것이 외부·맹검 심사나 새 표본에 의한 검증이 되지는 않는다.

### 결론의 한계를 정하는 질문
- 표본: 누가, 몇 명? 어느 범위까지 일반화할 수 있나?
- 측정: 무엇을 평균한 값인가? 순간값·활동별 정확도에 대해 말할 수 있나?
- 설계: 상관·일치 연구에서 인과(무엇 때문에 틀리는가)를 말할 수 있나?
- 시간: 그 기기의 그때 버전인가, 지금 버전인가?

## 출력
문제 기록표, 검증 범위 요약, "말할 수 있는 것 / 말할 수 없는 것" 목록.

## 남은 질문
결론은 새 자료(다른 사람, 다른 활동, 원시 시계열)로만 넓힐 수 있다. 같은 자료를 더 돌려서 넓힐 수는 없다.
