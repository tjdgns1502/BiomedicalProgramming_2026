# 다음 논문에도 사용할 요청 프롬프트

이제 요청의 범위는 **논문을 이해하고, 재현하고, 통계적 타당성을 검토한 결과를 처음 문서의 각 단계에 연결하는 것**입니다.

## 전달할 기준 프롬프트

[[4주차 과제 - 에이전트 실행 설계/05-prompts|전체 실행 프롬프트 v2.0]]

그 문서의 `[0. 입력과 목적]`에 논문·과제·데이터·작업 폴더·학습 노트 위치를 넣어 전달하세요. 나머지에는 초기 설명 구성, 의문→작업 변환, 역할별 제한, 문맥·쓰기 독립성, 기록, 파일 구조, 검토와 종료 조건이 들어 있습니다.

짧게 전달할 때:

```text
frailty-agent-workflow/docs/05-prompts.md의 v2.0 실행 계약을 적용해 줘.
먼저 논문의 연구 질문과 한 관측 단위의 데이터가 집단 결과가 되는 과정을
기존 concept/paper 형식으로 설명하고, 각 단계의 의문을 남겨 줘.
그 의문을 미공개 구현 조사와 통계적 타당성 검토로 나눠 작업화하고,
계획·환경·논문·구현·검토 역할에 필요한 문맥만 전달해 수행해 줘.
재현 비교와 검토 결과는 초기 문서의 해당 단계에 되돌려 넣어 줘.
새 HTML이나 별도 최종 보고서는 만들지 마.
논문: <경로>
과제: <내용 또는 경로>
데이터: <경로/공개 출처/없음>
작업 루트: <경로>
학습 문서 루트: <기존 Obsidian 노트 폴더>
```

## 사용자가 읽는 파일과 실행 파일

| 위치 | 역할 |
|---|---|
| 현재 학습 폴더의 `00-start` | 전체 연구 흐름과 주요 결과 |
| 각 `concept` | 통계·데이터 특징·방법의 일반 설명 |
| 각 `paper` | 논문 설명 → 의문 → 구현 비교 → 검토 → 갱신된 해석 |
| `analysis/src`, `data`, `runs` | 계산 코드·자료·실행 결과 |
| `analysis/tasks`, `memory` | 앞으로 생성할 작업 계약과 조정 기록 |

이번 기준에서는 학습 문서의 편집 원본을 Obsidian 폴더로 지정했습니다. 기존 `frailty-learning/source`는 유지할 경우 검토된 단방향 미러로 관리합니다. 과거 분석 결과의 근거 수준은 새 프롬프트 때문에 바뀌지 않습니다.
