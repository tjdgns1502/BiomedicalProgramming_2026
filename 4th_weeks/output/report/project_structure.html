1. 전체 구도: 스킬 vs 에이전트

이 프로젝트는 두 가지 종류의 "도구"를 사용했다. 스킬(Skill)은 현재 대화 안에서 내가 직접 따라가는 절차서(체크리스트)이고, 에이전트(Agent)는 별도의 독립된 맥락에서 작업을 위임받아 처리하는 하위 작업자다. 스킬은 "무엇을 어떤 순서로, 어떤 규칙으로 채워 넣을지"를 정하고, 에이전트는 "많은 파일을 뒤지거나, 독립성이 필요한 일"을 맡는다.

구분스킬 (Skill)에이전트 (Agent)
맥락지금 이 대화 안에서 실행됨별도의 독립된 대화(컨텍스트)에서 실행됨
목적반복되는 절차를 규칙대로 수행 (표 채우기, 검증 규칙 사전 명시 등)맥락을 많이 잡아먹거나, 독립성이 필요한 작업 위임
이 프로젝트의 예목표값 정리, 몬테카를로 검증 설계, NHANES 데이터 규칙논문 수치 추출, 데이터 구축, 코드 감사, 독립 재현

2. 스킬 (Skill) 3종

SKILL paper-reproduction-ledger

위치: .claude/skills/paper-reproduction-ledger/SKILL.md (프로젝트 상위 폴더 공용)

논문에 적힌 목표값과 우리가 계산한 값을 나란히 놓고 비교하는 output/tables/ledger.csv 원장을 관리하는 절차. 열 구성(source, table, row, col, target, ours, abs_diff, tolerance, status, cause, evidence), 허용오차 판정 규칙, status 값(match/mismatch/not reproduced/open), 그리고 불일치 원인 어휘 (data version, variable definition, sample exclusion, survey weights, method difference, paper typo, our error)를 정의한다. 목표값(target)은 한 번 적어두면 절대 수정하지 않는다는 규칙이 핵심이다.

이번 프로젝트에서: 논문의 Methods 절단점, Table 1~3, Fig. 1 수치 238개를 먼저 채우고(에이전트가 추출), 분석이 끝난 뒤 R/08_fill_ledger.R이 우리 값을 채워 최종 240행(match 37 / mismatch 56 / open 146 / not reproduced 0)을 완성했다.

SKILL monte-carlo-verification

위치: .claude/skills/monte-carlo-verification/SKILL.md

시뮬레이션으로 통계 방법이 이론대로 작동하는지 확인하는 절차. 실행 전에 통과 기준을 먼저 못박고 (99% 몬테카를로 구간 = 추정값 ± 2.576×SE), 반복 횟수는 우선 B=1000으로 빠르게 본 뒤 최종은 B=10000, 시드 고정 방식 (순차용 legacy seed vs 병렬용 L'Ecuyer-CMRG stream)까지 규정한다.

이번 프로젝트에서: R/01, R/02 (그리고 병렬화된 R/11, R/12)가 이 절차를 따라 "여러 그룹 비교를 반복하면 1종 오류가 얼마나 부풀려지는지"와 "p-값이 정말 균일분포를 따르는지"를 검증했다.

SKILL nhanes-survey-data

위치: .claude/skills/nhanes-survey-data/SKILL.md

NHANES(미국 국민건강영양조사) 데이터를 다룰 때 지켜야 할 규칙 모음: 파일 다운로드/캐싱 방법, 가중치 선택 (가장 작은 하위표본 기준), 주기(cycle)를 합칠 때의 가중치 공식(1999-2002는 WTMEC4YR×2/9, 2003-2016은 WTMEC2YR×1/9), svydesign()은 반드시 전체 파일로 만든 뒤 subset()해야 한다는 규칙, 제외 흐름 기록 방법을 담고 있다.

이번 프로젝트에서: nhanes-data-builder 에이전트가 이 스킬을 미리 불러온 채로 작업했다.

3. 에이전트 (Agent) 4종

AGENT paper-target-extractor

도구: Read, Glob, Write  |  모델: Sonnet  |  호출 시점: 매주 새 프로젝트 폴더가 만들어진 직후, 1회

논문 PDF(paper/)를 읽고 보고된 모든 숫자와 재현에 필요한 방법론적 선택을 파일로 뽑아낸다. 채팅에서 논문을 요약하지 않는 것이 규칙이다.

산출물: output/tables/ledger.csv(목표값 238행, ours는 공란), output/tables/paper_methods.csv(방법론 68행) — 이 두 파일이 이후 모든 분석의 기준이 됐다.

AGENT nhanes-data-builder

도구: Read, Write, Edit, Glob, PowerShell  |  모델: Sonnet  |  nhanes-survey-data 스킬을 미리 불러옴

NHANES 원자료를 내려받아 분석용 데이터셋을 만든다. 1999-2016년 9개 주기, 50세 이상, CBC 지표(NLR/MLR/SIRI/SII), Rockwood 방식 36항목 노쇠지수(FI), 논문이 명시한 공변량까지 구축한다. 사용자에게 절대 되묻지 않고 결정을 스스로 기록(decision log)하는 것이 원칙이다.

산출물: data/processed/frailty_cbc_pooled.rds, frailty_cbc_analytic.rds(N=14054), frailty_cbc_svydesign.rds, output/tables/exclusion_flow.csv, build_decisions.csv(33행) 등.

이 단계에서 잡힌 실수: 1999-2002 가중치 공식을 잘못 지정한 것, "돈 관리 어려움" 항목이 NHANES에 없다고 잘못 보고한 것(SAS 라벨이 아니라 문항 서두 문장을 읽은 오류), 비음주자 정의를 AND로 묶어 3646명을 불필요하게 제외한 것 — 세 건 모두 원자료를 직접 대조해 잡아내고 지시를 정정했다.

AGENT ai-error-auditor

도구: Read, Grep, Glob, PowerShell  |  모델: Opus  |  호출 시점: 결과를 원장에 넣거나 커밋하기 전, 매번

다른 에이전트나 내가 짠 분석 코드를 코드 수정 없이 독립적으로 감사한다. 그 주 커리큘럼(../docs/의 발표계획)에서 그 주의 "검증 과제" 항목을 체크리스트로 삼아, 실제로 코드를 재실행한 증거를 근거로 지적한다.

이번 프로젝트에서 잡은 것들: R/01, R/02의 통과율 집계 오류(의도적으로 깨지는 대비 검정이 섞여 있던 것), 시각화가 점을 옆으로 밀어 곡선과의 비교를 왜곡한 것, R/20의 의료이용 절단점(HUQ050)이 1999-2012년 구간에서 절대 채점되지 않던 버그, 2001-2002년 검사실 변수명 누락, 자가건강/당뇨를 이분형이 아니라 서열형으로 채점한 오류, 이완기혈압 0과 GPAQ 거부/모름 코드가 결측 처리되지 않은 것, 3단계 제외 인원 수 오기(13507→13659) 등.

AGENT 독립 노쇠지수 재현용 general-purpose 에이전트 (1회성)

도구: 기본 Read/Write만 부여  |  호출 시점: 1회, R/20과 완전히 분리된 상태로

"제작자와 검증자를 분리한다"는 원칙을 실제로 시험해 본 사례. nhanes-data-builder가 만든 코드나 36항목 목록은 전혀 주지 않고, 오직 논문의 Methods 원문(노쇠지수 평가 부분), 원자료 파일 목록, 저장 경로만 주고 완전히 새로 처음부터 노쇠지수를 계산하게 했다. 코드나 항목 목록을 흘리면 이 검증 자체가 무의미해지기 때문에 격리가 핵심이었다.

산출물: data/processed/fi_independent.csv → R/21_fi_independent.R(원본 그대로 보존), R/22_compare_fi.R이 두 버전을 비교(상관 r=0.999, FI>0.3 일치율 99.7%, kappa=0.991).

이 방법의 한계도 함께 드러났다: 완전히 독립적으로 만들었는데도 LDH/ALP 검사 변수명을 똑같이 잘못 붙인 실수가 두 버전 모두에서 나왔다 — 논문 자체가 모호하게 서술한 부분이라 "독립적으로 다시 만들기"로는 못 잡는 오류도 있다는 뜻이다.

4. R 코드 파일 전체 역할표

번호는 실행 순서를 뜻하지 않고, 작업 단계(검증 시뮬레이션 0번대, 분석 0-9번대, 데이터 구축 20번대)를 나타낸다. 모든 스크립트는 맨 위에서 set.seed()로 시드를 고정하고, 반복 작업은 expand.grid() + Map()으로 처리해 for문을 쓰지 않는다.

파일단계역할
00_sim_utils.R검증 준비시뮬레이션 공용 함수: 시드 생성(legacy/streams 두 방식), future_Map 병렬 그리드 실행기, 손으로 벡터화한 Jonckheere-Terpstra 검정(jt_p()).
01_multiplicity_inflation.R검증같은 자료에 여러 번 검정을 반복하면 1종 오류율이 얼마나 부풀려지는지 몬테카를로로 확인 (B=1000판, 이후 v2로 대체).
02_pvalue_uniformity.R검증귀무가설이 참일 때 p-값이 균일분포를 따르는지 확인 (히스토그램/QQ/KS 검정, B=1000판).
04_quartiles_boxplots.R분석NLR/MLR/SIRI/SII 사분위 절단점을 논문 절단점과 우리 표본 절단점(type 7) 둘 다 계산, 마커별 FI 상자그림 생성.
05_diagnostics.R분석마커별 aov(fi_score ~ quartile) 진단(등분산성 Levene/Bartlett, 정규성). 표본이 N≈14000이라 정규성 검정은 항상 기각된다는 점을 주석으로 명시.
06_group_comparisons.R분석마커×검정 그리드로 ANOVA→TukeyHSD, Welch ANOVA→Games-Howell, Kruskal-Wallis→Dunn을 각각 맞춰 실행, Bonferroni/BH 보정까지.
07_trend_tests.R분석선형 추세 + Jonckheere-Terpstra 검정, 논문 Table 2·3에 해당하는 로지스틱 모형(가중/비가중) 재현.
08_fill_ledger.R원장 완성04~07의 결과값을 ledger.csv의 남은 226개 목표값 칸에 채우고, 불일치마다 원인(사례 제외/논문 오타/미해결)을 근거와 함께 기록.
09_ai_error_healthcare.R오류 사례의료이용 절단점 버그의 전/후 노쇠 유병률 차이를 직접 재계산해 "AI 오류가 결과를 바꾼 사례"로 제시 (17.67% → 18.73%).
10_verify_jt_fast.R검증jt_p()가 PMCMRplus::jonckheereTest와 1500개 무작위 자료에서 완전히 같은 값을 내는지 증명(약 250배 빠름).
11/12_..._v2.R검증(최종)01/02를 병렬화하고 B=10000으로 늘려 최종 실행한 버전 (future.apply, L'Ecuyer-CMRG 스트림 시드).
13_verify_parallel.R검증병렬 실행 결과가 기존에 커밋된 순차 실행 결과와 완전히 동일한지 확인 (시드를 문자로 저장해 생긴 버그를 여기서 발견·수정).
20_build_analytic_sample.R데이터 구축NHANES 9개 주기를 합쳐 CBC 지표와 36항목 노쇠지수, 공변량을 계산하고 분석표본(N=14054)을 확정하는 핵심 스크립트.
21_fi_independent.R독립 검증격리된 에이전트가 처음부터 다시 짠 노쇠지수 계산 코드 (원본 그대로 보존, 경로 하드코딩 있음).
22_compare_fi.R독립 검증20번의 노쇠지수와 21번의 노쇠지수를 항목 단위로 대조 — 상관, 일치율, 정의가 다른 항목을 모두 표로 정리.

6. 요약: 이 프로젝트가 보여준 원칙

스킬은 "어떻게 채울지"를 미리 정해 즉흥적인 판단을 줄이고, 에이전트는 "누가 만들고 누가 확인하는지"를 분리해 같은 사람(같은 모델)이 코드를 짜고 스스로 검사하는 상황을 피했다. 실제로 ai-error-auditor가 잡아낸 의료이용 버그처럼, 제작자와 별개인 시선이 있었기에 발견된 오류가 여러 건이었고, 반대로 독립 재현 시험에서는 "완전히 분리해도 논문 자체가 모호하면 같은 실수를 반복할 수 있다"는 한계도 함께 확인됐다.
