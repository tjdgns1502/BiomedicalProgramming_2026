# 문맥 오염을 줄이는 입력·출력 계약

문맥 오염은 긴 대화뿐 아니라 **추정이 사실로 승격되는 것, 재현의 목표 수치가 타당성 판단의 목표가 되는 것, 이전 계획의 결과가 새 데이터 버전과 섞이는 것**에서 생깁니다.

## 정보의 상태

| 라벨 | 의미 | 승격 조건 |
|---|---|---|
| assignment_requirement | 첨부 과제에서 확인한 요구 | 원본 위치와 그대로 읽은 문구 |
| paper_reported | 논문이 보고한 내용 | PDF 쪽·절·표·각주 또는 보충표 확인 |
| codebook_verified | 원자료 변수의 의미·단위 | 해당 조사 주기 코드북 |
| observed_data | 실제 자료에서 계산한 상태 | 데이터 해시·코드·실행 ID |
| analyst_proposal | 학습자료 또는 에이전트의 제안 | 판단 근거를 기록하되 사실로 바꾸지 않음 |
| reproduction_candidate | 논문 결과를 설명할 후보 설정 | 모든 후보와 오차를 함께 보존 |
| unknown / conflict | 미보고 또는 출처 간 불일치 | 상충하는 근거를 병기; 다수결로 해결하지 않음 |

학습자료의 ‘논문 사실’ 표시도 원문을 대체하지 않습니다. 기존 설명은 출처를 찾는 색인으로 이용하고, 실행에 필요한 항목은 S01에서 원문·코드북으로 재확인합니다.

## 역할별 문맥

| 역할 | 받는 것 | 기본 입력에서 제외하는 것 |
|---|---|---|
| S 조사·데이터 계약 | 과제·논문·학습자료·코드북·데이터 메타정보 | 결과를 맞추라는 성공 기준 |
| B 타당성 계획 | 과제 요구·측정 정의·설계 정보·제한적 진단 | A의 후보 순위·목표 OR/p값·결론 맞추기 지시 |
| A 재현 | 원문 목표값·미보고 사항·데이터 계약 | 재현 일치를 타당성으로 해석하는 권한 |
| C 과제 실행 | 잠근 계획·고정 데이터·검정 가족 | A의 선택 후보를 근거 없이 채택하는 지시 |
| M 모의실험 | 검정 알고리즘·자료 생성 조건·평가 기준 | 실제 연구에서 원하는 유의성 방향 |
| V 민감도 | 정한 변경과 이유·기준 계획 | 결과를 보고 새 주분석을 고르는 권한 |
| G 감사 | 모든 계획·결과·실패·변경 로그 | 근거 없이 완료 상태를 승격하는 권한 |

B에게는 측정에 필수인 기준값은 전달합니다. 숫자를 모두 없애는 것이 목적이 아닙니다. A의 **일치 대상인 결과값과 후보 평가**를 분리하는 것이 목적입니다.

## 새 작업을 시작하는 절차

1. 작업 ID 하나를 고릅니다. 등록된 의존 작업의 인계가 검수됐는지 확인합니다.
2. `uv run workflow.py packet <ID>`로 입력 패킷과 해시 목록을 만듭니다.
   실행 직전 `uv run workflow.py check-packet packets/<ID>/<생성시각>`으로 입력과 패킷이 바뀌지 않았는지 검사합니다. 불일치하면 새 패킷을 만들고 변경 이유를 기록합니다.
3. 새 에이전트 문맥에서 시작합니다. 대화 전체를 fork하거나 지난 요약을 통째로 붙이지 않습니다.
4. 필수 자료가 없으면 필요한 항목과 이유만 `needs_input`으로 반환합니다. 다른 독립 작업은 진행할 수 있습니다.
5. 결과는 해당 작업의 `runs/<ID>/`에 저장하고 구조화한 반환서를 만듭니다.
6. 별도의 검수자가 산출물과 해시를 확인한 뒤 `handoffs/<ID>.json`과 요약문을 등록합니다. 작성 에이전트가 스스로 검수 완료로 표시하지 않습니다.
7. 다음 작업은 원래 대화 대신 검수된 인계 요약과 정확한 산출물 경로를 받습니다.

패킷 생성기는 기본 파일과 의존 인계의 해시를 남기고, 재현 트랙 인계를 B/C/M으로 자동 전달하지 않습니다. 반환 상태를 자동 판정하는 통계 심판이나 OS 보안 경계는 아닙니다. 모델에 같은 파일시스템 전체 읽기 권한이 있으면 패킷 밖 정보에 접근할 수 있으므로 역할 프롬프트와 접근 로그가 함께 필요합니다.

## 결과 노출과 계획 변경

이 대화의 조정자는 이미 논문의 결과와 일부 설정을 보았습니다. 새 작업의 문맥을 줄여도 그 사실이 없어지지 않습니다. `prior_exposure=true`를 기본으로 기록하고, 정말 새 작업자가 결과를 읽지 않았는지 구분합니다. 이 설계를 사전등록·맹검·독립 표본 검증으로 표현하지 않습니다.

계획을 고정한다는 것은 지금 시점의 계획 파일과 SHA-256을 남기는 것입니다. 변경은 가능하되 이전 파일을 보존하고, 이유·노출 정보·영향받는 작업을 기록해 새 버전으로 실행합니다. 공통 데이터 계약 변경 시 C/A/V의 관련 결과도 무효화하거나 재검토해야 합니다.

에이전트가 허용되지 않은 문맥을 읽었거나 결과를 본 뒤 결정을 바꿨다면 숨기지 말고 노출 로그에 남깁니다. 관련 판단을 결과에 노출된 판단으로 재분류하고, 그 판단을 새 주분석으로 조용히 덮어쓰지 않습니다.
